| 2 | DEFECT | completion popup in a shader | "gl_FragCoord is missing from the autocomplete list? And other seem to be missing as well..." | `glsl_docs.py` is generated from the Khronos es3.0 refpages and holds 88 builtin FUNCTIONS, `KEYWORDS` and `TYPES`; `intel/index.py` adds only `gl_FragColor` / `gl_FragData` as outputs. | 3 | UX | app restart on a feedback document | "It would be nice to save the current canvas textures of the passes and load them on app restart. E.g I have a shader which uses the previous pass in order to draw on the canvas. Drawing resets on each app restart. We should save the texture and load on restart." | Feedback history is `Document._feedback: dict[str, Canvas]`, one previous-frame canvas per feedback pass, swapped with the pass's live canvas in `_swap_feedback` at the frame boundary; it starts EMPTY on every `Document()` and `load_from_dir` builds none, so a reloaded document's first `u_prev` read is black (`tests/test_document_graph.py::test_feedback_starts_black` pins that). `UIDocument.save` already persists a user-bound raw texture as `textures/<pass>/<uniform>.bin` + `{size, components, dtype}` and `_load_uniform_value` reads it back through `gl.texture(size, components, data, dtype)` — the precision-preserving shape to mirror (`f2` canvases must not go through `texture_to_rgba8`, which clamps and quantises). Save runs at quit BEFORE GL teardown (`ui.run`: `app.save()` then `app.shutdown()`), on document switch and on every graph verb; there is no autosave timer. |
| 4 | UX + question | the FPS panel | "About our fps profiler: I have frame time 4.8 and gpu time 5.8 for one of my shaders... Is this correct? Can gpu time be larger than the frame time? Also, can we add some noticible colors for the performance metrics and also sort them by frame time..." | Correct, and expected on a GPU-bound shader: `frame` is the CPU wall of `update_and_draw` (swap included, the target-fps sleep in `run` excluded), a GPU span is a `GL_TIME_ELAPSED` query the CPU never waits on (no `gl.finish` in the frame, no `swap_interval` call anywhere), and the ring reads it two frames late (088 D2). The GPU can still be drawing frame F while the CPU submits F+1, so its time per frame is bounded by nothing the CPU span measures. The panel: `ui_primitives.py::_profile_rows` draws children in RECORDING order with no sort, and every number is `COLOR.FG_MUTED`; no semantic color token is used. `theme.py` has `STATE_OK` / `STATE_WARN` / `STATE_ERROR`. |
