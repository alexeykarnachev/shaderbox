A “empty space on the documents preview panel … even if a project has a lot of documents, a user rarely clicks on them” draw_document_preview_grid is given width / 2.6 and the panel's full height, and lays 150px tiles into it. Two documents fill one row; the remaining ~200px of height is empty at every project size below ~8 documents.
B “Script open and Graph open … maybe these should be just menu options?” Both are already commands — OPEN_SCRIPT (Alt+R) and OPEN_GRAPH (Alt+G) — in the Document menu. The panel rows are a third affordance for a verb that already has a menu item and a chord.
C “the document name input field occupies a solid amount of space, but how often will a user change the name? 1–2 times” NAME_INPUT_W = 180, always drawn, always editable, with its own caption row above it.
D “I don't like this red Reset button. It looks scary, but it doesn't do much” danger_button at the panel's right border. It resets histories, clock, script and videos — recoverable by re-running, and nothing on disk is touched.

found		 not reported by you — surfaced while reading the code The panel's button is hardcoded "Reset" while the command it duplicates is labelled "Reset document", so the same verb reads as two names. The grid's "New document" button hardcodes its label too. Both bypass command_label(), which Add pass and Import passes do use.

The one structural fact behind all four: every verb in this panel is already in the command registry with a label, a chord and a menu category. OPEN_SCRIPT, OPEN_GRAPH, RESET_DOCUMENT (F6), DELETE_DOCUMENT, ADD_PASS, IMPORT_PASSES. So every option below only removes widgets. None of them adds a mechanism.

D the collapse button you were unsure about

You asked whether to add a fold between the documents grid and the tabs, and then answered yourself: “maybe we should optimize the worst case for now and tune with these cheat collapse buttons only when we don't have other choices.” I agree, and here is the evidence for skipping it.

A fold buys width only in the folded state, and it buys it by hiding a panel you still want at rest. It also adds a persisted boolean, a restore path, and a second layout to verify in every frame test. Options A and B return the same width unconditionally, with no state and nothing to remember. Recommendation: do not build the fold. If A or B lands and the panel still feels tight, the fold is still available, and by then the worst case will have been measured rather than guessed.

· the Reset button, specifically

You are right that the tier is wrong. danger_button is the tier for verbs that destroy work on disk — Delete document, Delete pass, library reset. Reset touches histories, the clock, the script and videos, all of which come back by running the document again. It is loud because it was filed under the wrong tier, not because it is dangerous.

Today — a red block at the panel's right border, always visible, pulling the eye on every frame.

Reset

Proposed — a normal item in the document's context menu and the Document menu, where it already is, at its registered chord. No panel widget at all.
